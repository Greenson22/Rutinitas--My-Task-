# 03: Kaitan Akumulasi Berbasis ID Unik

**What to build:** Semua kaitan akumulasi lintas card dan internal kini menggunakan ID unik item sebagai identifikasi utama, dengan nama sebagai fallback untuk data lama. Edit relations dialog menyimpan ID di samping nama saat pengguna memilih target. Semua lookup akumulasi (internal accumulator, external card accumulation, dan prerequisite card linking) menggunakan strategi ID-first/name-fallback. Dua item dengan nama identik di card berbeda bisa dikaitkan secara tepat tanpa salah sasaran.

**Blocked by:** 01 (Fondasi Model Data — UUID dan isDisabled).

**Status:** ready-for-agent

- [ ] Edit relations dialog mengirim ID (`linkedSubjectId`, `accumulatorItemId`, `linkedExternalItemId`) bersamaan dengan nama saat pengguna mengonfirmasi
- [ ] Dialog controller (`updateItemNameAndRelationsData`) menyimpan field ID baru ke item
- [ ] Lookup akumulasi internal (`accumulatorItemName`/`accumulatorItemId`) di `updateProgressValueData` menggunakan ID-first, fallback ke name
- [ ] Lookup akumulasi lintas card (`linkedExternalItemName`/`linkedExternalItemId`) di `updateProgressValueData` menggunakan ID-first, fallback ke name
- [ ] Lookup prasyarat card (`linkedSubjectName`/`linkedSubjectId`) di `validateAndSetLinkedProgress` menggunakan ID-first, fallback ke name
- [ ] Lookup sinkronisasi lintas grup di `updateSubjectOverallProgress` menggunakan ID-first, fallback ke name
- [ ] Buat 2 item bernama "Latihan" di 2 card berbeda → kaitkan akumulasi item kecil ke salah satu "Latihan" → increment item kecil → hanya "Latihan" yang dikaitkan via ID yang bertambah nilainya
- [ ] Data lama (kaitan hanya punya name, belum punya ID) → kaitan tetap bekerja via fallback name-based lookup
- [ ] Simpan ulang data lama → field ID kaitan tertulis di JSON untuk lookup berikutnya
- [ ] `flutter analyze` bersih untuk semua file yang diubah
